# 共造 v0.8 运行与部署

本轮支持两种沙盒运行方式：Node.js 24 本地服务使用 SQLite；私人托管的 Worker 使用 D1 保存状态、R2 保存模型文件。网页经 `/api/v2` 请求服务端。两种方式均不控制真实打印机，不收款、不分账，也不查询真实物流。

本地与私人托管是不同的数据空间；没有自动同步或迁移。移动、桌面、微信工程不能直接复用私人托管浏览器的登录 Cookie，必须另行接入服务端认可的身份流程。

## 1. 本地启动

在项目根目录使用 Node.js 24 或更新版本。建议先安装锁定的开发依赖，以便运行构建与检查：

```sh
node --version
npm ci
npm start
```

默认访问 `http://127.0.0.1:3000`。本地运行入口为 `services/platform/local.mjs`，使用 Node 自带 HTTP、SQLite 和密码学模块；没有第三方服务运行依赖。`npm ci` 安装的是构建、迁移等开发工具，不会接通支付或设备。

```sh
npm test
npm run check
npm run build
```

这些命令的通过情况以本轮验证记录为准。`npm run api:demo` 仍运行旧的内存演示 API；它不提供本轮 SQLite 网页服务，也不能代替 `npm start`。

### 端口与数据位置

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `PORT` | `3000` | HTTP 端口；命令行 `--port` 优先 |
| `DATA_PATH` | `data/platform.sqlite` | SQLite 文件路径，相对启动工作目录解析 |
| `--host` | `127.0.0.1` | 仅支持 `127.0.0.1` 或 `0.0.0.0`；容器中需显式使用后者 |
| `--port` | 使用 `PORT` 或 `3000` | `npm start -- --port 3001` 可换端口 |

POSIX shell 示例：

```sh
DATA_PATH=./data/pilot.sqlite PORT=3001 npm start
```

PowerShell 示例：

```powershell
$env:DATA_PATH = '.\data\pilot.sqlite'
$env:PORT = '3001'
npm start
```

v0.7 本机注册与登录使用邮箱密码和 `coforge_account` HttpOnly 会话。匿名客户体验仍可建立旧沙盒工作空间，但商家接口必须先认证。账号会话有效期 7 天，退出即撤销；邮箱验证和密码找回未开通。原匿名空间仅在持有旧 Cookie、注册时明确选择接管后绑定；清除旧 Cookie 后不能仅凭邮箱自动找回。详情和第三方身份服务配置见 [v0.7 登录说明](INTERNATIONAL_AUTH_V0.7.md)。

本地服务默认只接受 `127.0.0.1`、`localhost` 和开发预览所需的 `terminal.local` Host；独立 HTTPS 部署需要通过认证配置显式设置 publicOrigin，并拒绝不匹配的 Origin 及跨站请求。不要把本地会话机制当成公网身份系统。

### 数据与备份

SQLite 开启 WAL；新上传文件的字节与模型元数据同事务提交，故障注入已验证失败时回滚。停止服务后，确认连接关闭再备份数据目录和数据库文件；运行期间只复制主 `.sqlite` 文件可能遗漏 WAL 中的事务。需要在线备份时，先实现受控 SQLite backup 流程并做恢复演练。

保留数据文件及原 Cookie 时，重启服务应继续看到原订单和模型。使用另一份 `DATA_PATH` 会得到另一套本地数据库。不要提交实际数据库、会话、模型或密钥到 Git。模型原字节在本地数据库中保存，删除数据文件会一并丢失。

## 2. 本地容器运行参考

仓库本轮不交付已验证的 Docker 镜像。以下是适合开发机的参考启动方式：挂载源代码只读，数据单独保留，只将端口发布到主机回环地址。

```sh
docker run --rm --name gongzao-sandbox \
  -p 127.0.0.1:3000:3000 \
  -v "$PWD:/app:ro" \
  -v gongzao-sandbox-data:/data \
  -w /app \
  -e DATA_PATH=/data/platform.sqlite \
  node:24-bookworm-slim \
  node services/platform/local.mjs --host 0.0.0.0 --port 3000
```

容器中的 `0.0.0.0` 让容器网络可达；主机侧的 `127.0.0.1:3000:3000` 仍限制为本机访问。使用 `http://127.0.0.1:3000` 访问，避免触发 Host 校验。

若需要经过反向代理供其他人访问，必须另外设计 HTTPS、可信身份、Host/Origin 白名单和请求限制。现有本地服务会拒绝外部域名，不能仅靠修改 Host、关闭跨站检查或复制浏览器 Cookie 解决鉴权。此参考命令不构成生产容器部署或商用安全验证。

## 3. 私人 Worker / D1 / R2 托管

### 产物与绑定

| 项目 | 配置/产物 | 责任 |
| --- | --- | --- |
| Worker 源码 | `services/platform/worker.mjs` | 同源静态文件、身份读取和 API 路由 |
| Worker 构建 | `npm run build` → `dist/server/index.js` | 把业务代码与网页资源打包为 ES module |
| 静态资源索引 | `generated/assets.mjs` | 构建生成，不是另一套业务实现 |
| 托管描述 | 项目 hosting 配置及构建复制件 | 启用 D1/R2，构建复制配置；服务入口与迁移按现有托管流程识别 |
| D1 绑定 | `DB` | `platform_workspaces` 工作空间状态 |
| R2 绑定 | `BUCKET` | 上传模型原字节；不开放公共桶下载 |
| 数据定义 | `db/schema.ts`、`drizzle/0000_small_the_liberteens.sql` | 受版本控制的数据库结构及首个迁移 |

缺少 `DB` 或 `BUCKET` 时 API 返回 `503 STORAGE_UNAVAILABLE`。Worker 不会在首个请求里偷偷建表；必须在目标环境应用迁移。构建成功只证明产物生成，不证明远端迁移、存储绑定或鉴权已经生效。

### 身份信任边界

本轮 Worker 只适用于项目的私人托管入口。可信托管网关鉴别登录用户后注入 `oai-authenticated-user-id`，Worker 将该身份作为工作空间 owner。调用方自报的 owner 参数不参与空间选择。

这个头本身不是密码学凭据；Worker 信任的是上游平台的鉴权与头清理保证。不得把同一 Worker 直接部署到公开来源、允许外部绕过网关后仍接受该头。迁到其他云、开放商家访问或提供 App API 时，应先加入服务端令牌验证、角色/组织映射、撤销机制和端到端隔离测试。

私人发布不是多角色权限模型。一个沙盒 owner 可在演示界面执行客户与农场主操作；正式客户不能拥有这些商家动作权限。

### 发布步骤

1. 使用已有项目的私人托管配置，核对 Worker 入口、`DB` 与 `BUCKET` 绑定，保持访问权限为 private。
2. 检查 `db/schema.ts` 与已提交迁移。仅当结构变更时运行 `npm run db:generate`，审查生成 SQL；不要在每次启动时生成新迁移。
3. 在独立预览环境按托管平台的迁移流程应用 `drizzle/` SQL，再执行 `npm run build`，检查 Worker bundle 与 hosting 描述齐全。
4. 通过该项目现有的 Sites 发布入口发布构建产物。仓库目前没有通用 `npm run deploy` 或 Wrangler 配置，不应臆造一条可用于任意 Cloudflare 账号的发布命令。
5. 在授权浏览器检查会话、上传、下载、报价、下单和刷新持久化。用另一测试身份确认原账户的订单与模型不可见；未登录访问受保护 API 应被网关或 API 拒绝。
6. 确认远端 D1 迁移、R2 写入、错误处理和沙盒标识后，记录部署版本与验证结果。保持真实支付、设备和物流开关关闭。

D1/R2 不具备跨服务事务；R2 写入后若 D1 版本比较最终失败，可能留下未登记的孤立文件，尚需垃圾回收。当前没有自动回滚、D1/R2 一致性备份或一键迁移本地数据的工具。恢复部署旧 bundle 不等于回滚数据库；有破坏性结构变更时应先制定可回退迁移和恢复方案。

## 4. API 调试与重试约定

所有 API JSON 响应设为不缓存；模型下载使用私有且不缓存的响应。普通浏览器界面使用同源请求。当前不开放跨来源 CORS，也不将通用 Bearer 请求自动映射为用户。

| 请求 | 作用与要求 |
| --- | --- |
| `GET /health` | 查看版本、存储类型、沙盒模式及真实支付/设备关闭状态 |
| `GET /api/v2/session` | 建立/检查本地会话，或检查私人托管身份及能力 |
| `GET /api/v2/workspace` | 获取当前 owner 的可见订单、模型和设备 |
| `POST /api/v2/models` | 原始二进制；`Content-Type: application/octet-stream`；编码文件名置于 `X-File-Name` |
| `GET /api/v2/models/:id/download` | 只允许下载当前空间登记且已保存的模型文件 |
| `POST /api/v2/quotes` | 模型 ID、材料、数量、单位、质量和收货地区；价格由服务端计算 |
| `POST /api/v2/orders` | 服务端报价 ID 和 `demoAcknowledged: true`；不能自定金额 |
| `POST /api/v2/actions` | 明确的演示动作、目标 ID 及所需确认信息 |

所有 POST，包括获取报价，必须带 `Idempotency-Key`：8–128 位，字符范围为字母、数字、下划线、点、冒号和短横线。网络中断或响应丢失时使用同一键与同一请求重试；创建一个新键代表新操作。不要把“未收到成功响应”解释为操作未执行。

JSON 请求体上限 32 KiB；模型上传总上限 20 MiB，解析还有格式和复杂度限制。业务失败不会自动切回本机状态或自动宣布成功。处理 `401` 为会话问题，`403` 为身份/来源拒绝，`409` 为状态或并发冲突，`413` 为容量/大小限制，`415` 为格式或内容类型错误，`422` 为模型几何错误；具体以返回 `error.code` 为准。

## 5. 可复现验收清单

以下是操作步骤，只有执行后才能标记为通过：

1. 本地启动后查看 `/health`，确认 `SERVER_SANDBOX`、`persistence: sqlite`、`realPayments: false`、`realDevices: false`。
2. 用页面上传 `tests/fixtures/cube-20mm.stl`，检查服务端几何和文件哈希；下载文件核对字节一致。另用 STEP/3MF 或设计图片验证进入工程审核，不伪造自动可制造结果。
3. 取得服务端报价并创建订单；刷新页面，再停止并重启本地服务，保留 Cookie 检查订单仍在。
4. 用同一键重放创建请求，检查没有第二笔订单；更改请求体却复用键应被拒绝。并发命令不能丢失已提交状态。
5. 订单生产完成后先保持待取件；未清台、错料或质检失败不能继续不适当的操作。质检、物流签收与客户验收各自检查。
6. 签收后打开争议，确认验收结算被阻断；关闭争议并验收后只得到模拟结算结果，资金移动为零。
7. 使用另一个浏览器配置或测试身份，确认看不到前一个空间的订单，猜测模型 ID 不能下载前一个空间文件。
8. 在私人托管重复关键路径，并单独记录 D1/R2、鉴权和迁移证据；不能用 SQLite 通过代替托管验证。

负向测试还应覆盖超大文件、损坏 STL、无幂等键、失效报价、重复使用报价、错误请求来源及存储暂不可用。压力测试要说明环境、并发数与请求类型；一项本地 smoke 不能形成生产吞吐或可用性承诺。

## 6. App 和微信接入状态

- 原生微信工程的 API 地址和身份适配器默认未启用。先实现 `wx.login` 服务端换码与短期会话，再设置 HTTPS 合法域名并做微信开发者工具和真机验收。AppSecret 仅存服务端。

- Android/Samsung、iOS、Windows、macOS、Linux 的原生依赖、签名、公证、安装测试和商店审核单独完成。源码存在、配置解析或网页能打开都不等于已生成可上架应用。

# v0.7 国际地址、支付规划与账号登录

日期：2026-11-09。此版本完善可运行的本机沙盒；真实支付、商家分账、国际物流与实机生产仍未开通。

## 登录与商家开通

| 使用位置 | 账号验证 | 商家资料 |
| --- | --- | --- |
| 本机 `START-WINDOWS.cmd` / Node 服务 | 共造邮箱密码注册与登录；已配置时可用第三方身份服务 | 登录后单独开通店铺 |
| 现有私人托管站点 | 保留托管平台身份，登录入口与退出由平台负责 | 平台验证后单独开通店铺 |
| 微信小程序与原生包装 | 服务端身份适配仍未交付；不能复制网页 Cookie | 未宣称已完成真机登录 |

QQ 邮箱、Gmail 和其他邮箱均可作为共造账号。这里输入的是为共造新设的密码，不是邮箱账户密码。密码长度为 12–128 字符；服务端用随机盐与 scrypt 派生存储，不保存明文。会话令牌只存摘要，浏览器使用 HttpOnly Cookie。此版本没有邮件发送、邮箱验证或密码找回：注册不会发送邮件，也不能据此证明邮箱所有权。

过去商家入口只有资料开通，本机通过匿名 Cookie 区分空间。现在未登录的本机用户不能访问商家接口。客户可继续匿名沙盒体验，但开通商家前必须认证。原浏览器仍有旧 Cookie 时，注册页可明确勾选接管原沙盒工作空间；服务端唯一绑定，撤销该空间旧匿名会话。未勾选会新建空间。丢失 Cookie 不按输入的邮箱推定旧数据归属，也不会自动合并第三方账号。

登录不会自动完成企业资质审核。当前一个所有者仍可在自己的空间中演示买卖双方，不能视为完整商业多商户权限体系。

## 六个第三方入口

微信、支付宝、X、Apple、QQ、Google 使用管理员部署的 OIDC 身份服务（例如 Casdoor）承接上游登录。网页只显示服务端允许的入口；未配置时按钮显示“待开通”，没有伪造的二维码、登录成功或跳转。

管理员需要：

1. 部署 HTTPS 身份服务，建立应用与回调地址。
2. 分别在对应开放平台申请应用，设置实际网站域名、回调与所需权限。微信网站扫码、App 登录、小程序登录不能混为一种凭据；支付宝证书/签名配置由身份服务处理。
3. 在身份服务配置对应 provider；按随包示例填写本地私密认证配置，通过 `GONGZAO_AUTH_CONFIG` 指向文件（建议命名 `auth.private.json`）。示例 `auth.config.example.json` 默认 `oidc.enabled:false`；配置后设为 true，并只保留已经真实开通的 provider 项。不得把密钥写入网页、Git 或下载包。
4. 在本地或独立部署完成真实账号的登录、取消授权、退出、故障与账号恢复验收后，再开放入口。当前没有上游应用凭据，未进行六家真实 OAuth 验收。

反向代理需保留 Host，认证配置的 HTTPS publicOrigin 决定 Secure Cookie；不信任任意 X-Forwarded-* 头。回调为 `publicOrigin + /api/auth/oidc/callback`。issuer 为 HTTPS origin，发现和认证端点严格限制在该身份服务。

协议使用授权码、PKCE S256、state、nonce 与 JWKS 签名校验；身份按 issuer + sub 绑定，不按相同邮箱自动合并。Casdoor 的 `provider_hint` 必须对应后台真实 provider Name，不是任意客户端 URL。

## 国家切换

`GET /api/v2/markets` 是地址规则和支付展示的共同来源。网页根据国家改变字段标题、顺序、必填项、邮编和区号提示。保留用户已有联系电话，不会因收货国家改变而强行改号；邮编保持字符串，不套用全数字正则。

| 国家 / 地区 | 主要差异 | 参考币种 |
| --- | --- | --- |
| 中国大陆 | 省、市、区县、详细地址；邮编兼容旧版本可选 | CNY |
| 香港 / 澳门 | 无邮编；香港保留区域，澳门以完整地址为主 | HKD / MOP |
| 台湾 | 县市、乡镇市区、邮递区号 | TWD |
| 美国 / 加拿大 | 州或省、城市、邮编 | USD / CAD |
| 英国 | 城镇、邮编；郡可选 | GBP |
| 德国 / 法国 | 地址、邮编、城市 | EUR |
| 澳大利亚 / 新西兰 | 按当地城区、州或邮编规则 | AUD / NZD |
| 日本 / 韩国 | 当地行政区标题与邮编顺序 | JPY / KRW |
| 新加坡 | 详细地址与邮编，无省州/城市必填 | SGD |
| 马来西亚 / 泰国 | 按各自地址元数据，避免要求不存在的字段 | MYR / THB |
| 其他地区 | 填真实两字母国家代码与完整地址，人工确认 | 不猜测币种 |

这些规则不验证实际可投递性。已保存的旧海外地址仍能读取；如果缺少新规则所需字段，测算返回 `ADDRESS_INCOMPLETE`，用户补充后继续，不会破坏旧订单地址快照。

## 支付与询价

选择国家后，支付方案展示随之切换。大陆以微信支付、支付宝、银联及银行卡为规划；海外按市场展示银行卡、PayPal、Apple Pay、Google Pay 等候选。全部 `enabled:false`、`NOT_CONFIGURED`。收货国家不能单独决定支付资格，最终还要核对平台主体、商户国家、结算币种、设备能力与通道审核。

当地币种只作参考提示；当前沙盒统一 CNY 记账，不把人民币数值改成美元符号，也不虚构汇率。国际运费、税费和交期尚未接承运商计费，海外订单进入工程询价，未定价不可付款。兼容 API 中审核报价的 `total:0` 是占位；网页显示“待工程报价”，不是免费。

新报价与订单保存国家、币种及支付规划上下文；更改地址会使未下单报价失效，已创建订单保留历史快照。客户付款、签收、验收、商家结算申请和资金到账是不同状态。沙盒验证不能证明真实支付已通过，不能将平台内部状态称为金融托管。

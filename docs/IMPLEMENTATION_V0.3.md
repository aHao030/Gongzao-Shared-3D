# 共造 v0.3 实施范围

本轮围绕三个用户动作调整：从独立入口进入商家工作台，查询已登记设备，发现并选择尚未登记的设备。网页视觉改为黑、白、灰，收起非当前角色的导航，减少同时展示的信息。

v0.2 的模型上传、报价、订单与模拟履约仍保留。本轮的设备登记册与原有沙盒生产设备分开：**检测并登记设备不会启动打印，也不会将设备自动加入真实接单产能。**

## 界面与身份

| 入口 | 用途 | 身份边界 |
| --- | --- | --- |
| `/` | 客户上传、报价与订单 | 沿用当前本地沙盒会话或私人托管身份 |
| `/merchant/login` | 独立商家入口 | 进入商家流程，不在网页另收集平台登录密码 |
| `/merchant` | 商家设备与订单工作台 | 商家资料和设备归当前所有者空间 |

私人托管版仍由站点登录提供身份；本地版的浏览器会话仍是沙盒身份。开通商家资料用于体验商家流程，不代表企业资质已审核、正式商家已入驻，或整个市场的客户/商家/操作员权限已经完成。

新的商家接口会检查当前身份及商家资料。旧 `/api/v2/actions` 是原有私人沙盒履约接口；本轮不会将它宣称为可直接面向公众开放的多角色权限系统。

## 设备发现与登记

设备发现采用商家本地网关：在与打印机相同网络的电脑运行，由它发起只读探测并向平台回报结果。托管网页及云端 Worker 不直接扫描商家局域网。

界面分开表示以下事实：

- 已登记：设备已经存在于当前商家的登记册。
- 已发现：本次探测找到候选设备，尚需选择并导入。
- 待授权：设备接口要求凭据，网关还不能确认可用能力。
- 在线或离线：依据近期网关心跳及最近服务探测结果计算，不证明打印机本体连接或制造任务就绪；OctoPrint 版本接口只确认服务可达。
- 演示设备：仅供体验发现与导入的样例，不是实际网络探测结果。

导入按来源网关和设备身份去重。相同来源的重复提交不能重复增加同一设备；设备身份、来源网关和扫描记录必须归属于当前商家。当前身份由网关、协议和设备标识共同确定。另以同一商家下相同协议且地址或设备标识相同检查跨网关冲突：已由其他网关登记时，拒绝重复登记和自动接管。即使旧网关已撤销，也不自动迁移归属；地址和标识同时改变时，没有可靠序列号仍可能无法判定为同一物理设备。失效或不完整的扫描结果不能静默当成真实在线设备。

### 当前容量与有效期

| 项目 | 本阶段限制 |
| --- | --- |
| 已登记设备 | 每个商家空间最多 200 台 |
| 网关 | 最多 8 个有效网关、40 条历史记录 |
| 配对令牌 | 30 天有效；可撤销；原始值只在首次响应提供 |
| 网关在线判定 | 最近 90 秒内有心跳 |
| 扫描 | 2 分钟有效；最多 100 个候选；保留数量和时间均有上限 |
| 商家变更幂等历史 | 最多 1,000 条，达到上限返回容量错误 |

这些是沙盒实现阈值，不是生产规模承诺。网关持续心跳与旧生产模拟记录的权限/容量独立；正式运营前仍需归档、可管理的设备身份和规范化数据模型。

## 实际接入边界

本轮优先实现 Moonraker 与 OctoPrint 的只读识别路线：同网卡子网的 mDNS 候选，以及商家配置的私有 IPv4 目标。单次至多 32 个目标、4 个并发探测；不支持 IPv6、USB、厂商云账户或通用 CNC 发现。协议兼容不代表所有品牌、机型和固件已通过验证，也不代表已完成文件下发、切片、开机、暂停、取消或硬件联锁。

真实扫描、授权和示例模式应明确区分；网关未连接或没有发现设备时，界面应显示原因或空结果，不补入样例设备冒充真实设备。生产动作保持关闭。

## 数据与凭据

商家资料、网关元数据、扫描记录和设备登记通过现有工作空间存储与版本比较持久化。本地使用 SQLite，私人托管使用 D1；本轮未引入独立的跨商家调度数据库。

私人托管入口还有平台级访问控制。可选 `siteAccessToken` 由操作者单独放在本地私密配置，用于平台服务访问；网页配对响应不包含该值。仅持商家网关令牌并不保证可以通过私人站点的入口。托管连接须单独验证，不能用本地配对测试替代。

网关凭据只供受限网关接口使用，不能代替浏览器登录、访问其他商家模型或发起制造。设备 API 密钥由商家配置在本地网关，不进入设备候选结果。配置文件、令牌及实际设备信息不应提交到源码仓库。

## 验证与后续

本轮测试数量、浏览器检查及发布结果由 [VALIDATION.md](VALIDATION.md) 统一记录；实现文件存在不等于测试通过。当前仍需真实农场网络、指定机型/固件、失联恢复、系统防火墙和权限场景的现场验收。

尚未完成：真实切片/CAM与生产派发、商业多角色及企业审核、正式支付/物流、原生 App 构建签名与商店审核。商家网关的只读发现是设备接入的一步，不替代这些工作。

使用步骤见 [商家指南](MERCHANT_GUIDE.md)，本轮变更追踪见 [任务日志](TASK_LOG.md)。历史基础见 [v0.2 实施说明](IMPLEMENTATION_V0.2.md)。

# 生产接入差距与验收门槛

当前 v0.2 已打通网页、统一 API 和持久化存储的服务端沙盒：本地使用 Node.js 24 与 SQLite，私人托管工程适配 Worker、D1 和 R2。网页可上传模型、获取服务端报价、创建订单并完成模拟履约；本地浏览器闭环和服务重启后的订单恢复已验证。远端迁移、存储及身份验证按发布证据单独记录，详见 [v0.2 实施说明](IMPLEMENTATION_V0.2.md) 和 [运行与部署](DEPLOYMENT.md)。

真实设备、支付、物流及客户/商家/操作员的生产权限隔离仍未接入。模拟付款与结算不会移动资金，生产状态不会启动机器。旧内存 API 和离线网关模拟器继续用于独立规则验证，不能当作已经接通的生产链路。

以下已有基础包含服务端沙盒与独立协议验证；上线门槛面向真实多商户交易。当前单工作空间 JSON/CAS、本地事务和基础文件检查不能替代正式账本、资源预约、隔离计算及现场验收。

## 已有基础

- 报价条款及制造版本指纹，服务端演示计价和时间区间。
- 商业产能预留与设备派发租约分离，状态迁移约束。
- 签名信封、文件完整性、幂等指令、本地就绪条件与开机未知状态演示。
- 验收、物流、支付、争议、退款和重复结算的准入判断。
- `node:test` 覆盖重复派发、开机超时、错误文件/就绪状态、取消竞态、交付结算门槛及本地 API 冒烟检查。

## 上线前必须完成

| 方面 | 尚缺工作 | 验收证据 |
| --- | --- | --- |
| 身份与权限 | 客户、商家、操作员和平台隔离；会话与权限审计 | 跨租户模型/订单访问测试被拒绝 |
| 持久性与并发 | 数据库事务、资源锁、幂等唯一键、outbox、恢复和账本 | 重启及多实例竞争不重复开机/结算 |
| 文件 | 私有对象存储、限额、格式解析、单位确认、版本、恶意文件隔离 | 超大/损坏/单位错误模型受控失败 |
| 计价与交期 | 切片/CAM 估时、商家参数、历史校准、日历和后处理 | 每类工艺误差指标与可履约报价样本 |
| 设备 | 厂商授权接口、认证机型清单、本地网关、遥测、清台确认 | 指定型号/固件/材料的现场验收 |
| 材料 | 实际库存、料卷身份、预留和消耗、损耗校正 | 并发订单不重复占用相同可用料量 |
| 支付 | 支付机构入驻、验签、实际冻结/分账、退款、对账 | 沙箱及小额真实闭环，受理与成功区分 |
| 物流 | 承运商订阅、验签、补查、异常、拆包、退货 | 伪造/乱序/重复/缺失回调测试 |
| 质检与售后 | 图纸与质量标准、证据、返工尝试、赔付与争议 | 质检失败/拒收时不能自动放款 |
| 运维 | 密钥托管、证书轮换、日志脱敏、告警、备份及恢复 | 演练报告与可复现恢复结果 |

## 五项关键现场测试

1. 重复支付通知、派发重试、网关重启一起发生，同一生产尝试仍只开机一次。
2. 指令已执行但应答丢失：任务进入未知状态，机器不释放，不自动重复启动；核实后恢复。
3. 文件篡改、错误配置、材料不足、未清台、离线、过期就绪信息任一存在时，机器不启动。
4. 取消与开机同时发生：系统只有一个明确执行结果；未确认停止前不退款为“未生产”、不释放设备。
5. 打印完成、签收、验收与结算各自独立：未取件不再开机，质检失败返工，争议阻断支付解冻，重复请求只结算一次。

## 首期边界

仅在受控 FDM 机型、已验证配置和已授权农场内试点。模型应由平台受控切片流程生成生产文件；客户自带 G-code 不直接下发。CNC、金属打印及复杂后处理继续保留商家工艺审核。预约、派发和资金状态未知时均转人工核实；本原型不承诺自动解除风险。

支付机构存在最长冻结期限，需在服务端设置期限监控和处置流程；平台数据库的争议状态不会无限期阻止支付渠道自动解冻。具体渠道能力、合同和商家资质应在接入前逐一确认。

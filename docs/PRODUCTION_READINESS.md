# 生产接入差距与验收门槛

本说明区分正在运行的平台服务、旧的独立规则实验和真实生产接入，避免将自动化测试通过解释为商用上线完成。当前版本仍是持久化沙盒：付款、制造、物流与结算均不调用真实执行渠道。具体变更和测试数量以 [验证记录](VALIDATION.md) 为准；本轮开源对照见 [v0.5 补缺清单](GAP_REVIEW_V0.5.md)。

## 当前平台实际实现

网页调用 `services/platform/` 的统一 API。本地由 Node.js 24 / SQLite 保存，托管服务由 Worker / D1 / R2 保存。按访问者身份分隔工作区与模型文件；在同一个演示工作区内，访问者可以体验客户及商家操作，这不是客户、供应商、操作员和财务之间的正式权限体系。

- 模型文件服务端登记、哈希和有限 STL 几何检查；STEP、3MF、图片及不支持的工艺进入工程审核。
- 账号地址保存、缺失时补填、修改地址使旧报价失效、订单地址快照。
- 服务端示例费率、数量/单位/质量约束、报价有效期、估算依据及指纹校验；日期窗口按日历天作参考、未扣除节假日，人工审核不承诺到货日期；不是来自真实农场的商业报价。
- 演示农场的 FIFO 排队、设备占用、材料/模板匹配、清台、取件与模拟质检；未接入真实产能、库存预留或自动切片。
- 模拟发货与物流签收、客户验收、结算申请/处理、退款申请/处理及争议阻断；结算尝试与退款请求各有结果关联标识，拒绝旧结果覆盖新请求。真实承运商、支付机构与银行未连接。
- 商家资料、网关配对、受限的只读协议发现、设备登记、探针证据、独立的网关/设备观察时效与身份冲突检查；目前路线仅为 Moonraker / OctoPrint。识别服务不代表已验证具体机型、固件或加工质量。
- 写操作幂等、SQLite 事务及 D1 工作区版本 CAS；模型按归属存储。当前工作区仍是有容量限制的 JSON 快照，未实现真实金融账本、生产 outbox 或独立资源锁。

网页、设备发现和模拟生产使用不同记录。登记真实协议服务不会把它自动加入演示报价农场，也不会产生打印指令。

## 旧独立验证，不属于已接通生产链路

`packages/domain/`、`services/api/` 和 `services/gateway-simulator/` 保留早期纯规则、内存 API 与离线协议实验。它们验证过以下概念：商业产能预留和派发租约分离、签名信封、文件哈希、命令幂等、就绪证据、开机结果未知、核对及清台释放。

这些模块没有形成当前网页到真实设备的执行通道。其测试成功不证明当前平台已经具备真实资源预约、网络命令签名、持久化派发恢复或机器控制能力。网关模拟器不发送 HTTP/TCP/串口指令，当前真实发现网关也只读取服务识别信息。任何未来复用均需明确接线、持久化及现场验收。

## 真实交易前需要完成

| 方面 | 尚缺工作 | 验收证据 |
| --- | --- | --- |
| 身份与权限 | 客户、商家、操作员、运营和财务的独立授权；跨角色审计 | 两个独立账号的跨租户模型/订单/地址访问被拒绝；商家无法代客户验收或自行放款 |
| 持久性与并发 | 独立订单/任务/金融事件记录，事务 outbox/inbox、资源锁、唯一事件键与恢复 | 多实例竞争、回调重复、任务重试和进程重启不重复开机/结算；历史能追溯 |
| 文件 | 隔离解析与切片、复杂/恶意文件限制、单位与版本确认、可制造性验证 | 超大/损坏/单位错误模型受控失败；自相交、薄壁、公差等未检项目不会被展示成已通过 |
| 计价与交期 | 与设备匹配的切片/CAM、商家参数、工作日历、历史校准及后处理 | 各受支持工艺有误差记录；已支付订单能满足报价时的产能条件；未支持工艺转人工 |
| 设备 | 厂商授权接口、指定型号/固件的验收清单、遥测、清台与安全就绪条件 | 现场正常/异常流程报告；失联、应答丢失和未知状态不触发重复开机 |
| 材料 | 料卷/批次身份、实际库存、预留、消耗及损耗校正 | 并发订单不重复占用同一可用材料；材料变更需要重新确认制造配置 |
| 支付 | 渠道产品入驻、验签、真实收款与延迟分账/解冻、退款、账本、对账 | 渠道沙箱及小额真实闭环；受理与成功分开；前端跳转不能伪造已付款或已结算 |
| 物流 | 承运商订阅、验签、补查、异常、拆包和退货 | 伪造/乱序/重复/缺失回调测试；签收不自动代客户验收 |
| 质检与售后 | 商家质量标准、照片/测量证据、独立返工尝试、争议和赔付 | 质检失败或拒收不能放款；返工不覆盖原任务历史；退款与结算不能同时成功 |
| 跨端 | 原生/微信身份适配、真实上传、支付回跳、签名构建与分发 | 每端单独构建和真机报告；微信与各应用商店审核结果；静态检查不代替实机通过 |
| 运维 | 密钥托管、轮换、脱敏日志、告警、备份与恢复 | 恢复演练、多实例故障注入、审计关联及生产告警记录 |

## 五项关键现场测试

1. 重复支付通知、派发重试和网关重启同时发生，同一生产尝试只开机一次。
2. 指令已执行但应答丢失：任务进入未知状态，设备占用保持；核实前不再次启动，也不因心跳超时自动当作已停止。
3. 文件哈希、模板、材料、清台、告警、授权或就绪时效任一不符合时不启动。
4. 取消和开机竞争：只允许一个确定结果；未确认停止前，不按“未生产”退款或释放设备给下一单。
5. 打印完成、取件、质检、签收、验收、结算申请及结果分开。争议/退款阻断结算，重复/迟到结果不导致重复支付或状态回退。

## 受控试点范围

首次真实试点限定已经验收的 FDM 机型、材料、工艺配置与授权农场。生产文件由受控切片流程生成；客户的任意 G-code 不直接下发。CNC、金属打印和复杂后处理保留工程审核、工艺认证与现场准备，不能套用塑料 FDM 的自动启动条件。

支付机构可能设置资金持有期限及自动释放规则。应在服务端记录每笔交易适用期限，并在到期前执行获准延期、处理争议或退款等已确认流程；平台数据库的争议字段不会改变渠道规则。具体接入前提见 [支付设计](PAYMENTS_DESIGN_V0.4.md)。

当前网页及本机服务可以演示业务流程；本说明不是可以对公网开放商业多商户交易或无人值守制造的声明。

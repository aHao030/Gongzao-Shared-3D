# 商家能力、方案与设备接入

本指南适用于 v0.8 网页和本地网关。商家可配置服务、审阅模型需求和提交方案。订单生产、付款、物流和结算仍是沙盒；真实设备探测为只读，不会启动打印。

## 1. 打开商家入口

本地启动项目后，浏览器访问 `http://127.0.0.1:3000/merchant/login`；托管版在项目域名后访问 `/merchant/login`。页面提供独立商家入口，客户首页仍保留在 `/`。

私人托管版使用现有平台身份。本机版先用共造邮箱密码账号登录，再输入店铺名称创建店铺资料；密码是为共造设置的密码，不是邮箱密码。已开通时进入商家工作台。资料开通不代表企业资质认证。详情见 [国际地址与账号登录](INTERNATIONAL_AUTH_V0.7.md)。

## 配置服务并确认模型需求

先维护自己能够提供的工艺、材料、尺寸范围和接单模式；不再只让客户填写设备参数。配置中的设备关联仅用于登记，不能据此启动真实设备。默认演示配置与真实设备登记须分别核对。

客户上传模型后，填写数量、材料偏好及可选用途、公差、颜色和交期。商家审阅模型与需求，必要时推荐材料，再提交制造方案、最终费用、预计制作工时、发货和运输天数。采购/生产成本及利润底线只在商家侧展示，客户看到最终方案与应付分项。

客户尚未确认时可以提交修订方案；修订产生新版本，旧版不能下单。确认会冻结模型、材料、价格、时间和地址快照。确认后的方案不能直接改价或换材料，需要另行处理变更，不能自动补扣款。手动方案通过客户确认后仍需生产工艺验证，当前不会自动向真实打印机下发任务。

具体字段、版本检查和当前边界见 [模型需求与方案确认](MODEL_WORKFLOW_V0.8.md)。同一所有者可在沙盒内切换客户和商家操作；尚未实现真实跨账号商家撮合与生产授权。

## 2. 查询已登记设备

点击“管理设备”，或访问 `/merchant#devices`，再点击“查询已接入设备”刷新登记册。这里展示平台已经保存的设备；尚未发现或尚未导入的设备不会计入已登记数量。

计数来自服务端。“最近已识别”只说明最近的只读协议观察仍有效，不代表设备已经准备好打印；例如 OctoPrint 版本接口有响应，不证明它已连接打印机本体。设备清台、材料余量、准确机型和现场工艺认证均尚未验证。

网关心跳有效期为 90 秒，设备观察有效期为 5 分钟。网关继续心跳不会延长打印机观察。网页根据服务端时间校准状态缓存的到期时刻；页面停留或后台恢复后，旧状态会降为“待检查”，不会一直显示为已识别。此时先点击“查询已接入设备”；若是设备观察过期，再点击“检测并添加设备”重新读取。查询登记册本身不会重新探测打印机。

点击每行“识别详情”，可以查看协议、只读探针、服务版本、最近观察、控制器连接状态以及当前能力。Moonraker `/server/info` 回报的 `ready` 或连接成功不等于生产许可；OctoPrint `/api/version` 不提供打印机连接证据，界面明确标为未验证。旧版网关仍可登记，但显示“旧版协议回报，建议重新检测”。新版识别也只是商家网关回报，不能当作平台已经完成实机认证。

| 状态提示 | 含义与处理 |
| --- | --- |
| 只读协议最近有响应 | 当前观察有效；仅协议读取，不能上传制造文件或开机 |
| 状态缓存已过期 | 网页显示的信息已到期，查询登记册获取当前服务端状态 |
| 网关未在线 | 检查网关进程、网络与授权，再查询 |
| 设备观察已过期 | 网关即使在线，也需重新检测设备 |
| 最近检测失败 | 结果不能用于刷新在线状态，排查后重新检测 |
| 地址与设备标识冲突 | 检查地址变更、代理配置和设备身份，不能重复添加或抢绑 |

## 3. 第一次连接真实网关

点击“连接本地网关”，填写网关名称，点击“生成网关配置”，再点击“下载网关配置”。下载文件名为 `gateway.private.json`，只供这台网关使用。将配置和项目源码放到与打印机相同局域网的电脑。安装 Node.js 24 后，在项目根目录运行：

```sh
node services/device-gateway/cli.mjs --config gateway.private.json
```

保持窗口运行，再回到网页点击“完成并查询”，刷新网关状态。网关主动向平台轮询任务；无需把打印机控制端口映射到公网。

配置结构如下。示例中的令牌是占位符，不能直接用于连接：

```json
{
  "platformUrl": "https://你的项目域名",
  "token": "从配对配置获取的网关令牌",
  "mdns": true,
  "targets": []
}
```

`platformUrl` 必须是平台根地址，不附加 `/merchant` 或 `/api`。同一电脑开发可用 `http://127.0.0.1:3000`，不需要额外站点访问令牌。本地浏览器账户、私人托管账户及其设备空间不会自动同步。

### 私人托管的额外访问要求

当前云端预览是私人站点。网关的 `token` 只证明它属于哪一个商家网关，不能代替托管平台的私人访问权限。非浏览器调用还需要由站点所有者获取获准使用的服务访问凭据，在本地私密配置中单独设置可选字段 `siteAccessToken`，或通过本机环境变量 `GONGZAO_SITE_ACCESS_TOKEN` 提供；程序将它用于托管平台要求的服务访问请求头。

网页下载的配对配置不会包含这个平台凭据，也不会自动获取它。未配置时，私人站点可能先返回登录跳转或拒绝访问，网关无法变为在线；不能通过反复检测解决。不要关闭站点访问保护来绕过此要求。需要先体验完整流程时，可使用同一电脑上的本地平台和本地网关。线上接口仍使用 HTTPS。本轮尚未验证真实私人托管网关及农场设备；无法取得平台服务访问凭据时，先使用本地配对流程，不将云端连接标记为成功。

### 自动发现与指定设备

网关监听 Moonraker / OctoPrint 支持的 mDNS 服务广播，只接受本机网卡同子网的私有 IPv4 候选。设备没有开启广播、网络隔离或防火墙阻挡时，自动发现可能为空；可以在本地配置中添加已知设备地址：

```json
{
  "platformUrl": "http://127.0.0.1:3000",
  "token": "从本地商家页面配对取得的令牌",
  "mdns": true,
  "targets": [
    {
      "protocol": "moonraker",
      "endpoint": "http://192.168.1.20:7125",
      "name": "工作室打印机一"
    },
    {
      "protocol": "octoprint",
      "endpoint": "http://192.168.1.21:5000",
      "name": "工作室打印机二",
      "apiKey": "设备要求授权时在本地填写"
    }
  ]
}
```

这些设备地址仅为配置示例。请替换为商家实际拥有并获准访问的设备地址。指定目标使用局域网私有 IPv4 地址，必要时可包含设备 API 的路由前缀；每次最多检测 32 个地址，最多 4 个并发。当前不支持域名目标、IPv6、USB 或厂商云账户发现。网关不进行全网段端口扫描，不跟随 HTTP 重定向，也不探测公共网站或云元数据地址。

设备密钥只保存在商家本地配置，不上传到候选设备列表。不要把真实令牌、密钥或私密配置提交到 Git。配对令牌只在首次创建响应中提供，刷新或重放不会再次显示原始值。凭据有效期为 30 天；无法找回或需要更换时，使用平台的撤销/重新配对流程，不把聊天记录或源码当作凭据存储。

## 4. 检测并添加设备

1. 确认网关在线，在设备中心点击“检测并添加设备”。
2. 网关读取受支持设备的识别接口，平台显示本次检测结果。
3. 核对设备名称、协议和来源，选择尚未登记且可导入的设备。
4. 点击“添加所选设备”后刷新登记册。同一网关中按相同设备身份重复导入，不会重复增加数量。若同一商家下另一网关已经登记了相同协议、地址或设备标识，系统会阻止重复登记与自动接管。同一网关的同一协议地址出现不同设备标识也会被阻止；一次扫描中同一协议地址返回多个标识，会整次拒绝这份回报。地址和标识都发生变化时，仍可能需要人工核对。

“已发现”与“已添加”是两个状态。需要设备授权、未得到可验证响应、扫描超时或设备不受支持时，不应把候选项直接视为可用打印机。扫描结果需在 2 分钟有效期内导入；超时后重新检测。补齐本地设备凭据或连接条件后，也需重新检测。

当前以 Moonraker 和 OctoPrint 协议识别为主。某品牌打印机有 Wi-Fi，并不保证它开放这些接口；CNC、金属和树脂设备不因此自动获得无人生产能力。

## 5. 没有设备时体验流程

点击页面底部“体验演示检测”，再确认“使用演示数据体验”，即可查看发现、选择、导入和去重行为。示例包含两台可添加设备及一台待授权设备。演示设备在单独区域展示，不计入真实设备数量。真实网关离线或没有找到设备时，系统不会自动补入演示设备。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 商家页无法打开 | 先确认本地服务已启动，或使用项目所属账户登录私人托管站点 |
| 网关一直离线 | 确认 CLI 窗口仍运行；配置的平台地址、令牌和网络可达性正确；私人托管另检查 `siteAccessToken` |
| 检测结果为空 | 确认设备与网关处于可互通的局域网；检查 mDNS 广播，或在 `targets` 填入已知设备地址 |
| 提示待授权 | 设备接口需要本地 API 密钥；配置 `apiKey` 后重新检测，不把密钥填写到设备名称等字段 |
| 检测到但不能添加 | 查看候选项授权状态和扫描是否有效；不能靠重复点击绕过限制 |
| 添加后数量没有增加 | 可能已登记；查询登记册核对设备身份，不应重复创建同一设备 |
| 已识别但不能打印 | 网关仅进行只读协议识别；“已识别”不是自动生产认证 |

完整实现边界见 [IMPLEMENTATION_V0.3.md](IMPLEMENTATION_V0.3.md)，实际测试结果见 [VALIDATION.md](VALIDATION.md)。

## v0.5 接口补充

`GET /api/v2/merchant/devices` 增加 `serverNow`，网关和设备增加 `freshUntil`。设备投影包含 `connectionReason`、`observedConnectionState`、`observationExpiresAt`、`verification` 与 `capabilityDetails`。这些是当前状态投影，不需要数据库迁移；旧设备记录仍可读取。

- `verification.level` 为 `DEMO`、`LEGACY_PROTOCOL_REPORTED` 或 `PROTOCOL_PROBE_REPORTED`；`modelConfirmed`、`hardwareVerified`、`processCertified` 当前始终为 `false`。
- `capabilityDetails.protocolRead` 为 `true`；`fileUpload`、`startPrint`、`cancelPrint` 为 `false`，不能由网关回报提升。
- 新版网关只通过既有的 GET `/server/info` 或 GET `/api/version` 读取探针证据。`probeEvidence` 仅保存有界的服务版本、控制器状态、连接标记和固定探针路径；设备密钥不进入回报。
- `DUPLICATE_ENDPOINT` 表示扫描内同址多标识；`DEVICE_IDENTITY_CONFLICT` 表示与已登记设备同址异标识。拒绝后不改变设备绑定。

官方接口依据：[OctoPrint 版本接口](https://docs.octoprint.org/en/main/api/version.html)、[Moonraker Server Administration](https://moonraker.readthedocs.io/en/latest/external_api/server/)。参考 [FDM Monster 2.0](https://docs.fdm-monster.net/blog/fdm-monster-release-2-0-0) 的设备管理与状态分层，未复制上游源码，也未因此宣称支持其全部机型。

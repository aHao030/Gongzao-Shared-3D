# 商家入口与设备接入

本指南适用于 v0.3 网页和本地网关。订单生产、付款、物流和结算仍是沙盒；本轮新增的真实设备探测为只读，不会启动打印。

## 1. 打开商家入口

本地启动项目后，浏览器访问 `http://127.0.0.1:3000/merchant/login`；托管版在项目域名后访问 `/merchant/login`。页面提供独立商家入口，客户首页仍保留在 `/`。

私人托管版需要同一站点账户登录。本地会话用于体验，不要求填写真实平台密码。首次进入输入店铺名称，点击“使用当前账号开通”；已开通时点击“进入商家工作台”。商家页面提供“概览”“设备”和“订单演示”三个主要区域。该资料不是企业资质认证结果。

## 2. 查询已登记设备

点击“管理设备”，或访问 `/merchant#devices`，再点击“查询已接入设备”刷新登记册。这里展示平台已经保存的设备；尚未发现或尚未导入的设备不会计入已登记数量。

计数来自服务端。在线状态依赖最近的网关心跳与探测记录；电脑休眠、网关退出或网络中断后，旧结果不能代表设备仍在线。当前“在线”主要说明受支持的设备服务可响应；例如 OctoPrint 版本接口可用，不证明它已连接打印机本体。在线也不代表已清台、材料就绪或允许自动生产。

## 3. 第一次连接真实网关

点击“连接本地网关”，填写网关名称，点击“生成网关配置”，再点击“下载网关配置”。下载文件名为 `gateway.private.json`，只供这台网关使用。将配置和项目源码放到与打印机相同局域网的电脑。安装 Node.js 24 后，在项目根目录运行：

```sh
node services/device-gateway/cli.mjs --config gateway.private.json
```

保持窗口运行，再回到网页点击“完成并查询”，刷新网关状态。网关主动向平台轮询任务；无需把打印机控制端口映射到公网。

配置结构如下。示例中的令牌是占位符，不能直接用于连接：

```json
{
  "platformUrl": "https://你的项目域名",
  "token": "从配对配置获取的网关令牌",
  "mdns": true,
  "targets": []
}
```

`platformUrl` 必须是平台根地址，不附加 `/merchant` 或 `/api`。同一电脑开发可用 `http://127.0.0.1:3000`，不需要额外站点访问令牌。本地浏览器账户、私人托管账户及其设备空间不会自动同步。

### 私人托管的额外访问要求

当前云端预览是私人站点。网关的 `token` 只证明它属于哪一个商家网关，不能代替托管平台的私人访问权限。非浏览器调用还需要由站点所有者获取获准使用的服务访问凭据，在本地私密配置中单独设置可选字段 `siteAccessToken`，或通过本机环境变量 `GONGZAO_SITE_ACCESS_TOKEN` 提供；程序将它用于托管平台要求的服务访问请求头。

网页下载的配对配置不会包含这个平台凭据，也不会自动获取它。未配置时，私人站点可能先返回登录跳转或拒绝访问，网关无法变为在线；不能通过反复检测解决。不要关闭站点访问保护来绕过此要求。需要先体验完整流程时，可使用同一电脑上的本地平台和本地网关。线上接口仍使用 HTTPS。本轮尚未验证真实私人托管网关及农场设备；无法取得平台服务访问凭据时，先使用本地配对流程，不将云端连接标记为成功。

### 自动发现与指定设备

网关监听 Moonraker / OctoPrint 支持的 mDNS 服务广播，只接受本机网卡同子网的私有 IPv4 候选。设备没有开启广播、网络隔离或防火墙阻挡时，自动发现可能为空；可以在本地配置中添加已知设备地址：

```json
{
  "platformUrl": "http://127.0.0.1:3000",
  "token": "从本地商家页面配对取得的令牌",
  "mdns": true,
  "targets": [
    {
      "protocol": "moonraker",
      "endpoint": "http://192.168.1.20:7125",
      "name": "工作室打印机一"
    },
    {
      "protocol": "octoprint",
      "endpoint": "http://192.168.1.21:5000",
      "name": "工作室打印机二",
      "apiKey": "设备要求授权时在本地填写"
    }
  ]
}
```

这些设备地址仅为配置示例。请替换为商家实际拥有并获准访问的设备地址。指定目标使用局域网私有 IPv4 地址，必要时可包含设备 API 的路由前缀；每次最多检测 32 个地址，最多 4 个并发。当前不支持域名目标、IPv6、USB 或厂商云账户发现。网关不进行全网段端口扫描，不跟随 HTTP 重定向，也不探测公共网站或云元数据地址。

设备密钥只保存在商家本地配置，不上传到候选设备列表。不要把真实令牌、密钥或私密配置提交到 Git。配对令牌只在首次创建响应中提供，刷新或重放不会再次显示原始值。凭据有效期为 30 天；无法找回或需要更换时，使用平台的撤销/重新配对流程，不把聊天记录或源码当作凭据存储。

## 4. 检测并添加设备

1. 确认网关在线，在设备中心点击“检测并添加设备”。
2. 网关读取受支持设备的识别接口，平台显示本次检测结果。
3. 核对设备名称、协议和来源，选择尚未登记且可导入的设备。
4. 点击“添加所选设备”后刷新登记册。同一网关中按相同设备身份重复导入，不会重复增加数量。若同一商家下另一网关已经登记了相同协议、地址或设备标识，系统会阻止重复登记与自动接管。地址和标识都发生变化时，仍可能需要人工核对。

“已发现”与“已添加”是两个状态。需要设备授权、未得到可验证响应、扫描超时或设备不受支持时，不应把候选项直接视为可用打印机。扫描结果需在 2 分钟有效期内导入；超时后重新检测。补齐本地设备凭据或连接条件后，也需重新检测。

当前以 Moonraker 和 OctoPrint 协议识别为主。某品牌打印机有 Wi-Fi，并不保证它开放这些接口；CNC、金属和树脂设备不因此自动获得无人生产能力。

## 5. 没有设备时体验流程

点击页面底部“体验演示检测”，再确认“使用演示数据体验”，即可查看发现、选择、导入和去重行为。示例包含两台可添加设备及一台待授权设备。演示设备在单独区域展示，不计入真实设备数量。真实网关离线或没有找到设备时，系统不会自动补入演示设备。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 商家页无法打开 | 先确认本地服务已启动，或使用项目所属账户登录私人托管站点 |
| 网关一直离线 | 确认 CLI 窗口仍运行；配置的平台地址、令牌和网络可达性正确；私人托管另检查 `siteAccessToken` |
| 检测结果为空 | 确认设备与网关处于可互通的局域网；检查 mDNS 广播，或在 `targets` 填入已知设备地址 |
| 提示待授权 | 设备接口需要本地 API 密钥；配置 `apiKey` 后重新检测，不把密钥填写到设备名称等字段 |
| 检测到但不能添加 | 查看候选项授权状态和扫描是否有效；不能靠重复点击绕过限制 |
| 添加后数量没有增加 | 可能已登记；查询登记册核对设备身份，不应重复创建同一设备 |
| 设备在线但不能打印 | 本轮网关只有发现能力，尚未接通真实生产派发 |

完整实现边界见 [IMPLEMENTATION_V0.3.md](IMPLEMENTATION_V0.3.md)，实际测试结果见 [VALIDATION.md](VALIDATION.md)。

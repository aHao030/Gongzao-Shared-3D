# 共造 v0.9.4 全流程质询与运营验收

2026 年 11 月 11 日。上一次验收以客户下单、商家生产和售后履约为主。把平台运营人员单独作为参与方后，需要确认谁可以授予运维权限、谁能核实最后一次成功连接，以及谁可以在保留客户隐私的前提下看到待处理业务。v0.9.4 为这三项提供了管理入口。

## 谁来处理什么

| 参与方 | 可执行的工作 | 检查边界 |
| --- | --- | --- |
| 平台部署负责人 | 在部署环境绑定首位管理员；在后台授予、调整或撤销运维、审计角色，管理节点 | 首管绑定不可变账号 ID。持有邮箱、注册顺序、商家身份和访客工作区 ID 均不能使账号成为首管。换绑和恢复需要部署权限。 |
| 运维管理员 | 查业务摘要、节点和审计；登记节点、轮换凭据、停用或撤销接入，以及暂停或恢复新订单受理 | 每次写入核对当前账号、角色与配置版本；重复操作复用请求标识。 |
| 审计人员 | 查看摘要、节点状态和最近的管理操作 | 服务端拒绝成员授权和节点写入，即使直接访问相应接口。 |
| 客户、商家 | 在原客户和商家入口上传模型、报价、操作所属沙盒订单 | 平台权限单独授予。管理摘要只提供数量，未开放跨空间客户地址、图纸、账号目录、逐单金额或模型下载。 |
| 已登记服务器 | 持专用节点凭据主动上报代理版本 | 平台按收包时间判断最近联通情况。制造任务领取、商家设备发现、开机和财务结算分别使用自身接口和权限。 |

## 顺着一次订单追问

| 环节 | 验收问题 | 本次实现或复验 | 继续上线的条件 |
| --- | --- | --- | --- |
| 注册与登录 | 客户账号或已认领的访客空间能自行变成管理员吗？ | 管理路由绑定本地认证账号 ID 或托管身份，管理员单独授权。不同标签页切换账号后旧操作需重新核对。 | 部署方为获批的社交账号、邮件找回与多因素认证分别进行真实供应商验证。 |
| 模型与需求 | 管理员能否只看业务积压，不读取客户模型？ | 业务统计查询在数据库内读取订单状态并聚合，不使用模型存储、地址接口或金额字段。 | 两家独立商家的一笔真实询价需额外验证投标可见性、选定商家的文件访问权及权限到期。 |
| 报价与确认 | 商家设备、切片及批量成本是否与客户接受的报价一致？ | 复验设备成型范围、模型版本、已确认切片、毛利底线及过期方案重新核价。 | 每种工艺以实际良品数、耗材、机时、后处理、返工与运费校准估值。 |
| 节点接入 | 登记一台计算服务器后，怎样知道它是否连接过？ | 登记后的状态是未连接，首次有效心跳才显示在线。缺少新心跳超过窗口后显示离线，停用和撤销后旧凭据失效。 | 从目标网络验证 HTTPS、代理、私有站点机器访问、开机自启和断网重连；在线状态只证明节点凭据最近成功上报。 |
| 派工与异常 | 节点心跳中断时，是否应补发一条实机指令？ | 节点注册单独管理连接状态；已有制造任务按自己的租约、模型和工艺版本恢复。商家仍需完成备机、取件与质检。 | 用登记型号、固件和材料逐台验证停电恢复、任务去重、清台及现场紧急停止。 |
| 平台维护 | 暂停接单会让已付款客户失去查件、退款入口吗？ | 负责人或运维可填写原因暂停接单。暂停和新单按数据库提交顺序裁定：暂停先提交时，即使新单请求已开始，写入也会被拒绝；订单先提交时，原请求可幂等重放。已成立订单继续履约和售后。 | 在部署现场同时暂停接单与提交订单，核对两种提交顺序，复验既有订单查询、退款和恢复接单。 |
| 发货与物流 | 出库条件未满足，后台会不会提示可以发货？ | 待发货计数核对质检、冻结款项、未发货、退款和争议。对实际保存的订单，开启争议或请求退款会移出计数，拒绝退款后恢复，发货后消失。 | 承运商沙盒需覆盖重复推送、异常件、退回和签收时间差。 |
| 验收与资金 | 运营人员看到待退款数量等于已经退款吗？ | 待退款和未结争议分别统计，一笔订单可同时计入两项。复验签收、客户验收、模拟结算和退款的状态约束。没有真实资金接口或管理员代客户验收操作。 | 接入支付服务商测试商户，验证延迟结算、幂等回调、审核责任、拒付与逐笔对账。 |
| 故障与恢复 | 在线报错、机器失联和没有订单，是否会混为一谈？ | 未连接、离线、停用、撤销有各自状态。统计失败返回不可用，真正无订单才显示零。配置冲突后需刷新。 | 在部署现场演练数据库备份和还原、节点密钥轮换、负责人换绑以及异常告警。 |

## 验证口径

业务摘要只统计实际写入的沙盒工作空间。一次请求至多检查最近创建的 32 个空间，超过范围返回部分统计标志。工作空间数量包含保存过业务数据的访客空间，不能读作注册用户数。选入范围的订单按质检、物流、支付、退款和争议状态计数；旧订单使用已有状态字段。紧凑存储的报价记录不会为询问订单数量而解压。服务端遇到损坏或无法识别的订单结构返回统计不可用。

独立用例覆盖空库、旧记录、报价压缩行、隐私字段、超过样本上限、数据读取失败，以及“质检通过 → 开启/撤回争议 → 申请/拒绝退款 → 发货”时摘要的变化。实际 SQLite 验证本地路径，SQLite 实现的 D1 接口替身验证查询契约。托管环境的大规模统计和容量仍需独立压测。

管理操作审计为最近记录，界面提供保留上限和已移出条数。现阶段日志并非永久、异地或防篡改的财务审计归档。备份恢复会回到备份时点，恢复后需核对授权名单、更新其间轮换或撤销过的节点凭据，再允许外部节点重新接入。

## 本次实际验收

全量测试 519 项，511 项通过，0 项失败。8 项需要当前环境缺少的 Trimesh、OR-Tools 或 PrusaSlicer 等外部制造工具，已明确跳过。跨端工程通过 288 项静态检查。浏览器检查了首页管理入口、空表单错误定位和首管开通提示，使用合成数据核对了后台概览布局。

在回环网络上用独立进程运行心跳代理，走通登记、上报、轮换和撤销。已绑定节点的制造服务在离线时停止领取新任务，仍可回传有效旧租约结果；停用或撤销后相应请求被拒绝。SQLite 在线备份覆盖已提交 WAL，恢复到新库后核对了模型字节与首管 ID。实测未覆盖真实云服务器网络、Windows ACL、托管备份还原或生产支付。

## 下一次商用验收

在预发布环境分别准备客户、两个独立商家、平台负责人、运维和只读审计账号。让同一模型获得两家报价，成交后只向选定商家开放履约资料。由商家完成小批量生产、质检和发货，客户验收后在支付服务商测试账本上核对结算金额。过程中让一台节点断线、提交一次重复回调并开启一笔退款争议。验收时对照账号、文件授权、制造记录、承运商事件、资金账本和审计留痕。当前版本中的跨主体交易、实机生产、真实资金和应用商店发布仍需上述外部环境与后续开发。

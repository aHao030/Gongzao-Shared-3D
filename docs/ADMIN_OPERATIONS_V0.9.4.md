# 共造管理中心使用手册

## 开通第一位管理员

**Windows 本机。** 先运行 `START-WINDOWS.cmd`，在普通用户入口注册自己要使用的账号。打开首页底部的“平台管理”，输入这个账号的邮箱和共造密码，复制页面显示的账号 ID。在同一份项目里双击 `ADMIN-WINDOWS.cmd`，核对数据库路径，按提示将该 ID 设为首位管理员。刷新后台即可生效。Ubuntu、macOS 和其他 Node.js 24 部署可运行 `npm run admin:setup` 打开同一向导。

首管绑定只识别账号 ID。在同一台电脑上有多份项目时，尤其要核对启动器所在目录和数据库。只知道注册邮箱时，可在管理主机执行 `npm run admin:setup -- lookup --email 你的注册邮箱` 找到账号。使用外置 SQLite 文件时给向导传入 `--db 文件路径`，或设置与主服务一致的 `DATA_PATH`。

**托管站点。** 打开 `/admin/login` 后通过托管平台验证身份。由有部署权限的负责人把指定账号在本项目显示的账号 ID 设为服务端运行变量 `GONGZAO_ADMIN_OWNER`，再部署该环境版本。受邀的访问者不会自动获得管理权限。独立部署使用已配置 OIDC 时，也应绑定共造本地为该身份建立的账号 ID。邮箱密码方式没有内置 MFA，使用统一身份服务的部署可由身份提供商配置 MFA。

## 交接和恢复管理员权限

- 在管理中心的“权限”页，首管可把已注册账号授权为运维或只读审计员，也可撤销授权。授权生效时服务器核对账号。运维可以管理节点、新订单受理和查看业务概况。只读审计员可以查看信息和操作记录。
- 独立部署在主机运行 `npm run admin:setup -- status` 查看当前绑定，使用 `history` 查看本机首管变动记录。交接命令为 `replace --previous 原ID --id 新ID`，解除绑定为 `clear --previous 原ID`，两者均接在 `npm run admin:setup --` 后。环境绑定优先于数据库中的绑定。托管版使用部署环境完成首管交接。
- 授权、节点变更、暂停及恢复接单写入后台最近 200 条操作记录。界面显示已移出记录数量。长期合规归档及外部告警需要另行部署。

## 接入一台服务器

1. 在“服务器”登记名称与用途。管理中心只在签发或轮换成功时展示接入凭据。若保存前关闭了窗口，轮换该节点的凭据。
2. 将界面提供的配置保存到节点机器，文件名可用 `server-agent.private.json`。配置含 `platformUrl` 和 `token`。远程地址使用平台 HTTPS 根地址；本机开发可以使用回环 HTTP。Linux/macOS 将文件权限设为 `600`，Windows 使用仅运行账号可读取的目录。
3. 将项目解压到服务器，安装 Node.js 24 或更新版本。在项目根目录执行下面的单次连接检查。去掉 `--once` 后，代理每 30 秒上报一次。

```sh
npm run server:agent -- --config server-agent.private.json --once
```

后台在 90 秒窗口内收到有效心跳会显示在线，首次上报前显示待接入。使用自托管站点时，请确认节点可访问域名和 HTTPS 入口。私有托管站点还需要托管平台允许的机器访问通道，可信部署运维可以给代理配置独立的 `GONGZAO_SITE_ACCESS_TOKEN`。不要将全站服务访问凭据发给商家。

**接入制造计算。** 需要该服务器承担模型分析、切片或排期时，先完成制造运算服务配置，再在平台主机生成绑定到节点的独立 worker 凭据：

```sh
npm run worker:configure -- --owner 工作空间ID --server-node 节点ID
```

平台侧使用生成的 worker 访问配置，节点侧使用对应的 worker 私有配置，按 [制造运算服务说明](MANUFACTURING_WORKER_V0.9.md) 配齐运行环境。节点离线时暂停新任务领取，有效的已领取任务可回传结果。停用或撤销节点后，绑定的 worker 请求也会被拒绝。既有未绑定节点的 worker 继续使用原准入方式。更换整台主机时，应同时轮换 worker 凭据。心跳可证明代理与平台之间最近一次通信成功，切片成功率、打印机故障与现场清台需要各自的证据。

## 业务处置

“概览”按实际保存的数据汇总待发货、待退款、未结争议及订单数。单次最多统计最近创建的 32 个持久工作区，超过时页面标明范围。一次退款与一笔争议可能指向同一订单。

有维护或产线异常时，运维可填写原因并暂停新订单受理。客户仍可询价，已存在的订单继续履约或售后，重复确认已经成交的请求会返回原订单。恢复后，未成交客户可在报价有效期内重试。后台不替客户验收，不执行资金转账。

## 独立服务器部署和恢复演练

基础本机部署可直接运行 `npm start`。使用已有 HTTPS 反向代理的 Linux 主机，可先准备 `auth.config.json`，将 `publicOrigin` 设为自己的 HTTPS 域名，并确保容器运行账号能够读取。代理应保留该主机名，转发到本机 3000 端口。容器启动及首管向导命令如下。

```sh
docker compose -f compose.yaml -f compose.admin.example.yaml up -d --build
docker compose exec platform npm run admin:setup
```

用 `GET /health` 查看版本和进程状态，`GET /ready` 检查工作区和管理控制表是否可读，托管版还会检查对象存储的读取通道。部署未准备好时就绪检查返回 503。需要真实农场或支付服务商的功能，在各自接入环节另行验收。

独立部署的 SQLite 备份、校验和恢复演练在持有数据库权限的主机执行。下列目录必须由运行账号控制，备份与恢复目标分别使用此前不存在的目录。

```sh
npm run admin:backup -- create --out ./data/backup-001
npm run admin:backup -- verify --from ./data/backup-001
npm run admin:backup -- restore --from ./data/backup-001 --out ./data/restore-001
```

将创建时输出的 SHA-256 另存到备份目录之外。校验和恢复支持 `--sha256 已保存的摘要`。恢复得到 `restore-001/platform.sqlite`，原库继续保留。备份内包含账号、会话、订单和模型文件，应按业务数据保护。正式切换前在隔离环境核对备份后发生的订单、退款、首管交接、会话与节点撤权，并更新旧凭据。外部身份服务、worker 配置和物流服务的凭据需要分别保存。托管 D1/R2 的备份和恢复使用对应托管环境的运维流程。

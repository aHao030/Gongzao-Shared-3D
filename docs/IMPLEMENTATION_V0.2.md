# 共造 v0.2 实施说明

v0.2 将网页的模型、报价和订单流程迁入服务端沙盒：浏览器请求统一 API，本地使用 SQLite，私人托管使用 Worker、D1 和 R2。制造报价来自服务端，订单与状态变更持久化，并通过工作空间版本比较处理并发写入。本版仍使用虚构农场、示例费率和人工触发的生产、付款、物流事件。

本文件描述本轮工程实现及后续任务；运行命令见 [DEPLOYMENT.md](DEPLOYMENT.md)。v0.1 的独立内存 API 与离线设备网关保留作规则示例，不是 v0.2 服务入口。实际执行结果以文末验证矩阵及 [VALIDATION.md](VALIDATION.md) 的对应版本记录为准。

## 交付边界

| 能力 | v0.2 实现范围 | 仍需完成的生产能力 |
| --- | --- | --- |
| 服务端业务 | 模型登记、候选报价、订单、设备与履约状态，统一服务端规则 | 真实客户、商家、操作员权限及跨商家交易 |
| 持久存储 | SQLite 本地状态；D1 托管状态；本地 BLOB / R2 保存上传文件 | 规范化业务表、账本、事务性事件、归档与恢复演练 |
| 几何处理 | 上传字节的 SHA-256；STL 基础几何与闭合检查；STEP/STP/3MF 及设计图片保留审核入口 | 完整 CAD 解析、薄壁/自相交/公差分析、隔离切片/CAM |
| 价格与交期 | 服务端示例费率、数量、地区、排队和备料影响；15 分钟报价快照 | 商家合同费率、真实切片机时、库存、工作日历与历史校准 |
| 生产流程 | 服务端模拟排队、材料与清台门槛、完工、取件和质检 | 农场网关持久执行记录、设备身份、认证工艺及实机联锁 |
| 支付与物流 | 独立模拟状态、争议与验收门槛 | 支付机构进件、验签、分账、退款、对账和承运商订阅 |
| 跨端 | 共用 API 客户端接口；保留原生微信及移动、桌面包装工程 | 微信登录换码、跨端身份、真机构建、签名、商店审核 |

“服务端沙盒”指请求和数据保存是真的，业务中的资金、设备及物流事件仍是模拟。沙盒中确认验收会立即设置模拟结算成功；生产版必须拆为结算请求、渠道受理、渠道结果查证和对账，不得把本动作直接接到真实转账接口。

## 数据模型与状态

`platform_workspaces` 当前一名所有者一行：`owner` 为主键，`revision` 为递增版本，`data` 为工作空间 JSON，`updated_at` 为更新时间。JSON 内包括 `schemaVersion: 2`、模型、报价、订单、设备及幂等结果记录。该 owner 是沙盒数据隔离边界，尚不是经过商户授权的完整组织与角色模型。

| 对象 | 关键字段与约束 |
| --- | --- |
| Model | 文件哈希、格式、版本、尺寸、体积、审核标识；服务端依据上传字节登记，不能接受浏览器自报几何替代解析 |
| Quote | 模型哈希与版本、工艺版本、费率版本、数量/地区/单位、分项费用、交期和过期时间；指纹绑定完整快照 |
| Order | 引用唯一报价，保存报价快照；同一报价不可重复创建不同订单；模型变更需重新报价 |
| Device | 农场、装载材料、工艺版本、床面及材料就绪、当前订单和清台代次 |
| Idempotency | 键、规范化请求摘要、原结果、时间；相同键与相同请求重放结果，相同键与不同请求拒绝 |
| Uploaded file | 本地保存在 SQLite BLOB；托管保存在 R2，以所有者哈希及模型 ID 定位；对象键隔离不替代 API 鉴权 |

本地另有 `local_sessions`（令牌摘要、owner、过期时间）及 `local_model_files`（owner、模型 ID、字节）两张表；它们不属于托管 D1 的用户登录模型。

订单独立保存 `productionState`、`paymentState`、`logisticsState`、`acceptanceState`、`settlementState`、`disputeState` 和 `refundState`。界面 `status` 是组合后的显示值，不是唯一事实来源。示例主线为：报价 → 模拟下单/付款 → 排队或模拟打印 → 完成待取件 → 取件清台并质检 → 模拟发货 → 模拟签收 → 客户验收/模拟结算。

质检失败不能发货；设备未取件清台不能接下一任务；材料不匹配保留排队；签收本身不结算；争议阻断验收结算。当前沙盒只允许审核中或排队订单直接取消。真实开机后的取消、未知执行核实及返工尝试仍需独立生产编排实现。

## 单工作空间 JSON 与 CAS 的阶段限制

存储先读取 `revision` 和 JSON，在内存执行纯命令，再用 `WHERE owner = ? AND revision = ?` 比较并更新。新工作空间用 `INSERT OR IGNORE` 竞争创建；版本冲突时重新读取并重算。SQLite 当前最多尝试 40 次，D1 最多 10 次，耗尽后返回 `CONCURRENT_UPDATE`。客户端重试写操作必须复用原幂等键。

此方式适合私人演示的短状态变更，减少持久化与状态规则之间的不一致。它有明确边界：

- 一个 owner 的任意报价或订单写入都竞争同一行；数据量和并发增长后会放大序列化、解析及写入开销。
- 每次冲突都会重新执行命令；命令内不能直接发真实付款、设备启动、邮件或快递订阅等外部副作用。
- 当前没有跨工作空间资源预约、全平台库存唯一约束、资金复式账本或事务性 outbox。
- SQLite 新上传文件的 BLOB 与工作空间元数据在同一事务中提交；故障注入已验证回滚。托管 D1/R2 不具备跨服务原子事务：R2 写入后若 D1 CAS 最终失败，可能留下未登记的孤立文件，仍需垃圾回收、失败重试及一致性核查。
- `reset` 清空演示订单和报价，将模型列表与设备恢复为内置示例，但保留幂等历史；它不是完整文件删除或隐私删除操作，也不释放所有操作容量。
- 当前容量阈值为每空间 500 笔订单、100 个模型、6,000 份报价和 2,000 条幂等记录。序列化 JSON 按 UTF-8 编码后限制为 1 MiB（1,048,576 字节）。这些限制是本阶段应用阈值，不是数据库产品的通用容量承诺。
- 未建立自动清理、分表、业务历史迁移、统计查询和正式导出流程。达到容量后需维护者处理，不能通过重置推断所有历史都已删除。

下一阶段先把订单、报价、生产尝试、资源预约、事件、幂等记录和结算账本拆为有唯一约束的记录，再按事务边界迁移。迁移需要保留模型与报价版本、历史事件和原幂等结果；不能通过丢弃演示约束来扩容。

## 模型与计价的实际限制

上传支持 STL、STEP、STP、3MF，以及 PNG/JPG/JPEG/WebP 设计图片。非 STL 文件保留后进入工程审核；图片不能直接报价制造，需建模并确认尺寸。本阶段不解码这些 CAD 容器或图片内容，不假称已完成三维解析。STL 最多 50,000 个三角面；ASCII STL 最多 8 MiB；模型登记大小上限 20 MiB，HTTP 层还会检查请求大小。闭合判定包含退化面、边出现次数与方向检查，但没有证明自相交、壁厚、公差或工艺可制造性。单位必须由客户确认，毫米与英寸影响服务端尺寸和体积换算。

只有合适尺寸、闭合 STL、PLA/PETG、已覆盖地区等命中沙盒规则时生成自动计价；其他工艺和模型走工程询价。估时仍是基于几何和示例费率的公式，没有运行 PrusaSlicer、OrcaSlicer 或 CAM。页面金额不应被当成商家真实报价，也不能用于真实收费。

## P0：按纵向切片推进真实试点

沿用用户指定的 Matt Pocock 工程方法，把每项工作拆为包含界面、接口、数据与验收的可交付行为。以下为实施任务，不是已完成能力或已创建的 GitHub Issue。

| 切片 | 用户可完成的行为 | 前置 | 验收证据 |
| --- | --- | --- | --- |
| P0-01 身份与组织 | 客户登录；已审核商家只能操作自己的设备与订单；平台操作有审计 | 无 | 双租户与三角色越权测试；令牌吊销和过期；微信登录服务端换码；不接受客户端自报 owner/role |
| P0-02 持久订单与事件 | 同一真实请求在重试、服务重启及并发下只形成一笔订单 | P0-01 | 规范化表与唯一键；事务性 outbox；迁移/回滚演练；两个实例争抢同一预约的结果可复现 |
| P0-03 文件与认证报价 | 客户上传后获得可制造性结果及绑定切片版本的报价 | P0-02 | 私有存储、解析隔离、配额、超时；损坏/超限文件受控失败；真实切片耗材/机时与实机样本对照 |
| P0-04 产能及材料预约 | 客户选定报价，产能和料卷只被一笔有效预约占用 | P0-02、03 | 预约到期、迟到付款、换料、缺料及跨实例竞争测试；预约与物理作业锁分离 |
| P0-05 支付与退款 | 客户通过正式渠道付款，平台依据渠道确认更新订单 | P0-01、02、04；支付产品开通 | 验签、去重、查询补偿、退款与对账；不采信前端成功页；签约后的小额真实闭环 |
| P0-06 一台认证设备 | 已授权农场的就绪设备收到受控文件并开始一笔任务 | P0-03、04、05；现场授权 | 固件/材料/模板清单；网关持久幂等；启动应答丢失进入未知；重复事件不重开、不自动改派 |
| P0-07 取件至发货 | 农场主收到完工通知，清台、记录质检并提交真实运单 | P0-06 | 未取件不释放；QC 失败进入返工；运单上传与揽收分开；物流回调验签、乱序、重复与补查 |
| P0-08 验收至结算 | 客户验收后渠道完成分账，争议或退款时暂停放款 | P0-05、07 | 结算请求唯一；渠道受理与最终成功分离；签收不直接放款；超时冻结预警、对账及争议处置 |
| P0-09 受控跨端发布 | 同一用户在 Web、微信及一个目标 App 看到一致订单 | P0-01、08 | 合法域名、真实登录、上传/断网/重试；目标系统真机和签名安装；商店材料与审核记录 |

P0-06 首批限定一个已授权 FDM 机型、固定固件和少数材料。金属、树脂及 CNC 仍保留工程审核与现场确认；联网能力不能替代工艺、夹具和联锁验证。

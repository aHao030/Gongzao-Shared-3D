# 共造 · 开源对照与补缺清单 v0.5

核验日期：2026-11-08。核验对象为本仓库 v0.4 基线、下列项目的官方文档及本轮修改。采用这些项目的业务边界作为设计参考；没有将它们的源码复制进本仓库，也没有把上游设备能力算作共造已接入的能力。

本轮继续完善可运行的服务端沙盒。真实切片、实机开打、支付机构收款与商家转账、承运商查询、原生账号登录和应用商店发布，分别需要后续接入与验收。

## 开源对照发现

| 对照项目 | 官方文档可以确认的能力 | v0.4 的具体缺口 | 对共造的处理方向 |
| --- | --- | --- | --- |
| FDM Monster | 2.0 发布说明包含打印队列、G-code 分析、估时/材料元数据及任务历史 | 商家侧“发现的设备”和生产沙盒分离，但能力层级与新鲜度的说明不足；实际队列仍是演示农场单设备 FIFO | 清楚展示识别协议、最近探测时间、证据期限和只读能力；再以认证设备与生产尝试建立真实任务队列 |
| Moonraker | 队列使用独立 `job_id`，有 `ready/loading/starting/paused` 状态；相同文件允许多次入队 | 文件、订单与制造尝试尚未在真实网关形成可恢复的关联 | 真实派发以生产尝试 ID 幂等，保存上游 job ID；超时进入“结果未知”，核实前禁止重新开机。队列控制本轮不启用 |
| OctoPrint | 文件 API 区分上传、选择、切片与启动；`effectivePrint` 表示上传时实际是否启动 | 本平台仅实现版本/服务探测，尚无上传或启动回执 | 设备卡按能力显示；不把发现成功或文件上传成功标记成生产成功 |
| PrusaSlicer | 官方 FAQ 说明估时依赖与实际设备一致的配置，包括运动参数 | 现有价格和机时由体积、材料、数量及层高近似计算；几何检查不能证明可制造 | 报价明确标注估算依据与未核验项；保留模型/单位/模板版本；真实定价以后置隔离切片任务及商家费率为输入 |
| Medusa | 支付模块区分 payment collection、session、授权等阶段；Marketplace 需扩展 vendor 与订单关联 | 客户验收和模拟结算同一步完成；退款/争议缺少足够的独立处理中间状态；单所有者工作区不是商业多方权限 | 拆分验收、结算与退款动作，并防重复/竞态；真实多商户授权和支付渠道仍单独实施 |

以上是从官方能力和本仓库实现作出的工程判断，并非声称任一开源项目提供本平台所需的全部交易闭环。许可证采用边界见 [v0.4 对比](OPEN_SOURCE_COMPARISON_V0.4.md)，实际引入时仍需固定版本、逐文件与依赖检查。

## 本轮修正记录

### 履约与资金流程

- 客户确认验收后仅进入“已验收、待申请结算”，款项仍处于模拟冻结状态；另行申请结算后，再记录模拟处理成功或失败。
- 结算结果必须匹配当前 `attemptId`；失败可以重试，旧尝试归档，迟到结果不能覆盖新尝试。
- 退款分为申请和处理。结果必须匹配当前 `requestId`；拒绝后可以再次申请，历史请求保留。取消未生产的已付演示订单也先申请退款，不把提交申请当作退回成功。
- 未解决的争议或退款阻止后续派发、发货和结算；它们不等于机器已经停止。批准模拟退款前必须完成取件且没有设备占用。
- 模拟结算申请处理期间，以及已经模拟结算的订单，暂不接受新退款/争议。真实渠道中在途退款与转账的竞态仍需独立实现，不能用此限制代替生产售后方案。

### 跨端契约

- 共享客户端新增退款申请契约；客户客户端不能调用商家/运营的模拟结算或退款处理动作。
- 小程序远端订单使用服务端验收、结算、退款和争议字段显示当前阶段，不把“客户已验收”显示为“商家已到账”。
- 小程序新建本机演示订单分别展示付款、物流签收、客户验收、结算申请与结算完成；旧演示阶段保留兼容。
- 真实微信身份仍未接通，远端模式保持禁用；本轮契约测试没有使用真实微信账号或支付通道。

### 设备发现证据

- 设备详情区分演示、旧版协议登记与带探针证据的协议识别；具体机型、实机和工艺认证均未通过，页面不会把它们显示成已验收。
- 只读探针记录固定 GET 路径、服务版本及有限的控制器状态；不保存上游密钥。能力仅开放协议读取，上传、启动和取消仍关闭。
- 网关在线证据为 90 秒，设备观察证据为 5 分钟，二者分别判定。网关心跳不会延长设备观察；页面按服务端时间校准，使过期状态自动降级。
- 同一扫描内，同一协议地址出现多个设备标识时拒绝整批报告；同地址与已登记设备身份冲突时禁止导入，不能重复登记或抢绑。扫描失败不能刷新设备在线证据。
- 以上通过自动化探针/网关/HTTP 测试验证；尚无真实局域网、具体打印机型号和固件的现场验收。

### 报价依据与有效期

- `quote-evidence.mjs` 在生成指纹前把估算依据加入报价快照：几何近似或人工审核、模型分析器版本和说明、演示队列任务数、设备状态、各阶段机时与运输时间。
- 保留服务端解析得到的 `analysisVersion` / `analysisNote`，不再在模型登记时丢失；自相交、壁厚、公差、支撑等未检项目保持明确提示。
- 报价明示未运行切片器、未经实机校准、未预留产能，并显示报价有效期；过期时要求重新测算，服务端仍执行最终校验。
- 自动估算报价增加预计收到日期区间，按日历天参考窗口显示，明确未扣除节假日。人工审核报价不提供未经确认的到货日期或生产估时。
- 估算证据参与报价指纹，修改证据后不能沿用原报价下单。模型、地址、金额和制造配置的既有约束继续生效。

### 本轮验证范围

全量自动化测试 **155 项通过**；跨端静态检查 **267 项通过**；语法与 JSON 检查 **65 个文件通过**。其中新增的 3 项报价证据测试覆盖分析元数据、日期依据、手工询价不承诺日期、队列归属及证据篡改使报价失效。

浏览器已验证旧 v0.4 订单继续模拟打印、取件质检、发货、物流签收和显式客户验收。签收后仍待客户验收，客户验收后款项仍为模拟冻结、订单待申请结算。此处不把页面按钮、静态检查或自动化假设备当作真实制造/支付/微信真机验收。

后续浏览器验证、构建和部署记录以 [验证记录](VALIDATION.md) 为准。

## 推荐边界

- 客户端负责提交意图、展示价格与履约证据。价格、订单归属、支付结果和可执行动作由服务端决定。
- 交易订单和生产任务分开。退款、返工、分批生产需要新的任务/尝试记录，不篡改旧任务历史。
- 切片服务只处理受控模型与工艺配置；制造网关只接收经过授权的任务。客户上传的任意 G-code 不直接透传机器。
- 网关身份、站点访问身份与支付渠道凭据分开，密钥保留服务端或商家本地，不能进入网页、小程序或下载源码。
- 支付渠道确认收款、客户验收、申请向商家分账/解冻以及银行到账分别记录。物流签收、浏览器回跳及人工点击不能代替渠道结果。
- “协议可识别”“接口已适配”“指定型号/固件实机已验收”“当前现场可执行”分别判定，不使用一个“已接入”标签概括。

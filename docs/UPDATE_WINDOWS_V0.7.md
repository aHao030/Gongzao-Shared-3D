# Windows：把现有共造 v0.6 更新为 v0.7

这是本地项目的代码更新工具。请在您的 Windows 电脑上运行；对话中无法直接访问您的 D 盘。

1. 把新版 ZIP **完整解压到一个新的文件夹**，不要直接覆盖旧项目，也不要解压到旧项目内部。
2. 在原来的共造命令窗口按 **Ctrl+C** 停止服务。更新期间不要重新启动共造。
3. 在新版文件夹双击 **UPDATE-WINDOWS.cmd**。它默认更新您的这个目录：

   `D:\Gongzao-Shared-3D-v0.6-Download\Gongzao-Shared-3D-v0.6-Download\Gongzao-Shared-3D-v0.6`

4. 看到“更新完成”后，进入上述旧目录，双击 **START-WINDOWS.cmd**。旧文件夹名字仍可保留 v0.6，里面代码已经更新。

如果旧项目在其他位置，可在命令提示符中切换到新版文件夹，然后运行：

```bat
UPDATE-WINDOWS.cmd -TargetPath "D:\我的项目\Gongzao-Shared-3D-v0.6"
```

工具会验证旧项目的 `package.json` 名称和版本、新版更新清单的每个文件及 SHA-256。它拒绝同一目录、互相嵌套的目录、磁盘根目录和链接路径，不会根据任意目录内容进行整目录复制。请使用完整 ZIP，不要单独移动更新脚本。

更新前，会将所有准备覆盖的旧代码备份到旧项目旁的 `原文件夹名.backup-时间-随机值` 目录。备份中的 `code` 文件夹保留原目录结构，`UPDATE-RECEIPT.json` 记录被覆盖和新增的文件。如果更新中途失败，工具会尝试回滚已经替换的代码并明确报告结果；若提示回滚不完整，请先保留整个备份，在恢复完成之前不要启动平台。需要手工恢复时，将备份 `code` 中的文件按原路径复制回项目；新增文件清单在回执的 `added` 字段中。

**代码备份不是数据库备份。** 更新器不复制、不覆盖、不删除 `data`、`.env`、设备配对私密配置、`node_modules` 或 `.git`，也不删除旧项目中用户添加的其他文件。现有账号和订单是否成功迁移，还需要应用启动后的迁移逻辑与测试保障。第三方平台账号仍需您自己的开放平台配置；更新不代表已经开通真实支付或设备执行。

工具需要 Node.js 24 或更新版本。它检查 Node 服务进程和默认 SQLite 文件占用情况，不会结束进程。不需要管理员权限，也不会修改全机 PowerShell 执行策略；CMD 中的 `-ExecutionPolicy Bypass` 只对本次启动的 PowerShell 进程生效。如果组织策略禁止脚本，请联系该电脑管理员，不要自行修改全局策略。

开发打包时，在最终源码稳定并把新增文件加入 Git 暂存区后运行 `node tools/create-update-manifest.mjs`，再打包完整目录。该命令只使用 Git 已跟踪的可更新文件生成 `UPDATE-MANIFEST.json`，忽略未跟踪的个人文件。不要在生成清单后继续修改源文件；需要修改时重新生成清单。清单提供完整性检查，不提供发布者签名验证。

本次交付在隔离临时目录验证了 Node 更新引擎与本地启动器；Windows PowerShell 入口尚未在真实 Windows 机器上运行验证。

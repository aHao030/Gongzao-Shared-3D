# 共造 · 共享3D打印 v0.8

连接个人创作者与制造商家的跨端工程。v0.8 围绕“上传模型、提出需求、商家给出方案、客户确认”整理操作流程；保留黑白界面、国际地址、本地账号登录与批量制造收益保护。

模型上传、报价、订单和履约状态保存在服务端。**制造报价、付款、打印、物流与结算仍为沙盒模拟。** 新网关只读取设备识别信息，添加设备不会启动打印或产生真实费用。

## 立即运行

安装 **Node.js 24**，全部解压项目。Windows 双击 `START-WINDOWS.cmd` 启动并打开网页；macOS / Linux 分别使用 `start-macos.command` / `start-linux.sh`。

已有 v0.7 的用户，先停止旧服务，将新版完整解压到另一个目录，再从新包双击 `UPDATE-WINDOWS.cmd`。默认更新 `D:\Gongzao-Shared-3D-v0.6-Download\Gongzao-Shared-3D-v0.7`，先备份代码并保留数据与私密配置。其他路径可用 `-TargetPath` 指定。详见 [Windows 更新说明](docs/UPDATE_WINDOWS_V0.8.md)。

也可以在包含 `package.json` 的目录执行：

```sh
node services/platform/local.mjs
```

Windows 也可在资源管理器中打开项目文件夹，在地址栏输入 `cmd` 后执行：

```bat
node services\platform\local.mjs
```

保持命令窗口开启，在同一电脑访问：

| 地址 | 用途 |
| --- | --- |
| `http://127.0.0.1:3000` | 客户上传、报价与订单 |
| `http://127.0.0.1:3000/merchant/login` | 独立商家入口 |
| `http://127.0.0.1:3000/merchant` | 商家工作台 |
| `http://127.0.0.1:3000/health` | 服务运行状态 |

本地启动不需要先执行 `npm install` 或 `npm ci`，也不要直接双击 `dist/index.html`。端口被占用时加 `--port 3001`，并使用对应地址。`127.0.0.1` 指当前电脑，不能直接作为其他电脑或手机的访问地址。

SQLite 默认保存在 `data/platform.sqlite`。本地商家现在必须先注册或登录共造账号，再开通商家资料；QQ 邮箱、Gmail 或其他邮箱均可作为账号。密码是新设的共造密码，不是邮箱密码。邮箱验证、邮件找回与企业资质审核尚未开通。旧沙盒空间可在持有原浏览器会话时，经注册页明确选择接管；不要提前清除浏览器 Cookie。

## v0.8 模型需求与商家方案

客户从上传模型开始，确认单位、数量与材料偏好；材料可以交给商家推荐。用途、颜色、公差和交期等为补充需求，客户无需填写温度、速度或支撑等设备参数。

商家维护可提供的工艺与材料配置，再根据模型与需求提交制造方案。客户查看最终材料、价格和交期，确认当前版本后才能生成模拟订单；方案修改后需要重新确认，已确认订单保留快照。详细步骤和实施边界见 [模型需求与方案确认](docs/MODEL_WORKFLOW_V0.8.md)。

本轮仍是同一所有者空间中的买卖流程沙盒。商家自报能力、标准模拟报价与已登记真实设备分别记录；能力配置不等于实机验证，提交方案不会自动启动真实打印机。真实多方订单路由、切片、设备执行、收款和结算仍待接入。

## v0.7 国际地址与账号登录

- 国家选择驱动地址字段顺序、必填项、邮编和联系电话区号提示。内置 16 个国家/地区规则及其他地区模板；地址只在账号资料中填写，缺地址时在测算前补填。
- 支付规划随所选国家显示：大陆优先微信/支付宝/银联，海外展示银行卡、PayPal、Apple Pay / Google Pay 等拟接入方式。它们均标为未开通；没有真实扣款或汇率换算。
- 海外订单仍先工程询价，国际运费、税费和交期人工确认。历史报价及订单保留当时的国家与支付上下文。
- 本机独立部署支持邮箱密码注册、登录、退出；第三方微信、支付宝、X、Apple、QQ、Google 通过管理员配置的 OIDC 身份服务连接，缺凭据的入口禁用。
- 私人托管网页保留现有平台登录，不在平台身份旁另造密码会话。商家账号认证与店铺资料开通是两个步骤。

参阅 [v0.7 国际化与登录说明](docs/INTERNATIONAL_AUTH_V0.7.md) 与 [Windows 更新说明](docs/UPDATE_WINDOWS_V0.7.md)。

## v0.6 批量计价与收益保护

- 商家进入工作台的“计价”，按演示农场设置材料采购价、设备机时成本、人工、包装和风险预留；可设置目标利润率、每单最低利润和每设备小时最低利润。
- 报价按包围盒估算板数，按板分摊准备成本、按件计算材料及后处理。FDM 总挤出机时随件数增加，不把一板多件误当成只打印一件的时间。
- 制造价同时满足三项利润底线。默认 30%、5 元/单、5 元/设备小时是可修改的演示假设，不是行业平均值或收益承诺。
- 客户看到制造总价、平均单件价、预计板数、平台费与运费；采购成本和收益计算只在商家页显示。当前沙盒所有者可扮演买卖双方，不代表生产级多商户权限完成。
- 商家应收为制造价加运费，平台服务费单列；客户退款仍以客户支付总额计算。旧版已完成结算不重写，旧版处理中总额结算不能直接成功。
- 计价参数修改后，旧报价须重新测算，已下单的价格和成本快照保持不变。未运行真实切片器，不跨客户合板或等待凑板。

计算例子、来源与验证边界见 [批量计价说明](docs/BATCH_PRICING_V0.6.md)，本机更新见 [v0.6 升级说明](docs/UPGRADE_V0.6.md)。

## v0.5 查漏补缺

- **报价可解释**：费用明细展示几何估算依据、排队项数、预计日期与有效期，并在报价中保留分析版本。过期报价须重新测算；工程询价不承诺金额或日期。
- **设备识别有边界**：服务可访问、观察是否过期、协议能力与实机认证分开展示。新增识别详情，同址异标识不能重复添加或抢绑。
- **验收与结算分离**：客户验收后仍待结算；商家在订单演示的“结算与售后”申请，再模拟成功或失败结果。失败可重试，旧结果不能覆盖新申请。
- **退款闭环**：客户可申请整单退款，商家演示批准或拒绝。待退款/争议阻止派发、发货和结算；运行中的设备不会自动停止，批准退款前须释放设备。取消未生产已付款订单也须处理退款。
- **保留历史**：旧版订单、账号地址和设备登记继续读取，保留当前及历次模拟处理记录。

本轮参考 FDM Monster、Medusa、OctoPrint/Moonraker 和 PrusaSlicer 的功能边界；未复制上游源码或宣称已集成这些完整系统。详细差距与后续优先级见 [查漏补缺记录](docs/GAP_REVIEW_V0.5.md)，本机更新见 [v0.5 升级说明](docs/UPGRADE_V0.5.md)。

## v0.4 地址与费用测算

- 首次进入客户网页时完善账号资料，也可以稍后填写。托管网页使用平台身份；v0.7 本机版增加邮箱密码账号。
- 首页不再显示收货地区选择或详细地址。点击“测算费用”时，如果未保存地址，会先弹出地址表单；保存后继续报价。
- 地址由服务端按当前身份保存，不写入浏览器本地持久存储。账号资料中可修改，修改后原报价失效，已创建订单保留当时的地址快照。
- 省区映射到原有沙盒费率；未覆盖区域与海外地址进入人工询价，不静默套用华东运费。仍未接入承运商的实际运费接口。
- 微信工程增加资料页，但真实微信登录、支付和真机验收仍未完成。

详细步骤见 [地址与升级说明](docs/CUSTOMER_ADDRESS_V0.4.md)。

## 支付设计范围

页面“支付与结算”展示接入方案，演示订单按钮明确为“模拟付款并下单”。真实支付通道尚未开通，不采集银行卡信息、不发起收款或商家转账。

拟支持微信支付、支付宝、国际银行卡、PayPal、Apple Pay / Google Pay及经审核的地区支付方式。按平台注册地、商家国家、币种及通道能力筛选，不同时承诺所有地区均可使用。付款、验收、分账/解冻与银行到账将分开记录，争议/退款阻止结算；物流签收不代替客户确认。官方通道存在持款上限与自动释放规则，详见 [支付设计](docs/PAYMENTS_DESIGN_V0.4.md)。

## 商家使用

从独立入口登录，再建立商家资料后，可以查询已登记设备。要发现局域网中的真实设备，先在商家工作台配对网关并下载配置，然后在商家的电脑运行：

```sh
node services/device-gateway/cli.mjs --config gateway.private.json
```

回到设备中心进行检测，核对候选结果后选择导入。当前私人托管站点另有服务访问要求：网关配对令牌不代替站点权限，需要由操作者在本地配置 `siteAccessToken`；网页不会下载或收集该平台凭据。本地平台与网关同机运行时不需要此项。网关支持 Moonraker / OctoPrint 的只读识别路线；真实设备接口授权在本地配置。没有网关时可以明确选择演示流程，系统不会用样例冒充真实检测结果。

详见 [商家操作指南](docs/MERCHANT_GUIDE.md)。私人托管网页不能直接扫描你的局域网；本地网关、真实机型及网络条件需要现场验收。

## 检查与构建

```sh
npm test
npm run check
```

需要构建托管 Worker 时，再安装锁定的开发依赖：

```sh
npm ci
npm run build
```

`npm run test:load` 是本地功能负载样本，不代表生产容量。执行结果以 [验证记录](docs/VALIDATION.md) 为准，不把配置解析或生成源码视为真机通过。

## 工程组成

| 目录 | 作用与状态 |
| --- | --- |
| `dist/` 顶层网页资源 | 模型需求、方案确认、独立商家入口和设备流程；调用服务端 API |
| `services/platform/` | 领域规则、HTTP、本地 SQLite 与托管 D1/R2；保存模型需求、方案版本、商家资料和设备状态 |
| `services/device-gateway/` | 本地只读发现网关；轮询受限扫描任务，不接受打印启动指令 |
| `db/`、`drizzle/` | 托管数据库定义和迁移 |
| `apps/weapp/` | 微信小程序工程，含账号资料页；远端登录和真机仍待适配 |
| `apps/mobile/` | Android / iOS Capacitor 包装工程，尚未签名及真机验收 |
| `apps/desktop/` | Windows / macOS / Linux Tauri 包装工程，尚未交付签名安装包 |
| `apps/shared/` | 跨端 API 客户端和受限网页资源准备流程 |
| `services/gateway-simulator/` | 原有离线生产协议模拟；与新只读发现网关用途不同 |
| `services/api/`、`packages/domain/` | 保留 v0.1 演示接口与领域回归；当前网页使用平台服务 |
| `tests/`、`apps/tests/`、`tools/` | 自动化、静态检查及负载样本 |

## 边界与正式部署

- 私人托管身份与本地浏览器会话分别保存数据，不自动同步。新的商家入口和资料开通不等于企业资质审核完成。
- 设备登记与原有模拟生产设备分开。发现到设备不代表已经认证工艺、材料、清台状态或自动开机能力。
- STL 上传、几何检查与示例计价保留；STEP、3MF 和图片进入工程审核，当前未替代完整 CAD、切片或 CAM。
- 真实多方商家权限、支付通道与会计账本、物流回调、制造派发和现场故障恢复仍需实现。旧沙盒履约接口不能直接作为公网商业权限系统。
- Android/Samsung、iOS、桌面和微信还需分别完成身份接入、原生构建、签名、真机与上架审核；当前没有原生鸿蒙 HAP 交付。
- 本地服务默认仅供本机访问，不应直接暴露到公网。网关配置及密钥保留在商家本地，不提交到源码仓库。

# 共造 · 共享3D打印 v0.2

连接个人创作者与制造商家的跨端项目。本版已将网页操作接入服务端：模型上传、服务端几何分析、报价、订单、设备排队和履约状态均可持久保存。**制造伙伴、加工参数、付款、打印、物流与结算仍为沙盒模拟，不产生真实生产或资金转移。**

## 立即运行

安装 **Node.js 24 或更新版本**，解压项目，在项目目录执行：

```sh
npm start
```

浏览器打开 `http://127.0.0.1:3000`。本地运行与业务测试无第三方运行依赖；SQLite 数据默认保存在 `data/platform.sqlite`。首次打开建立本地沙盒会话，刷新或服务重启后继续使用原订单。不同浏览器会话互相隔离；它不是正式会员注册或商家认证。

```sh
npm test
npm run check
npm run test:load
```

如需构建托管 Worker，先安装锁定的开发依赖：

```sh
npm ci
npm run build
```

## 已实现的完整沙盒流程

上传 STL → 服务端重算几何与文件 SHA-256 → 比较三家示例报价 → 创建订单与模拟冻结付款 → 材料/清台条件满足后模拟开打 → 打印完成待取件 → 清台质检 → 保存模拟运单 → 模拟签收 → 客户验收与模拟结算。

服务端保存报价快照及订单使用的文件版本；价格使用整数分。重复请求复用幂等键，不重复创建订单。金额、状态、用户 ID 不从客户端直接采用。当前一个身份可以在自己的沙盒内扮演客户和农场，**尚未实现商业多方商家权限与真实账本**。

STL 最大 50,000 个三角面；文件最大 20 MiB，ASCII STL 最大 8 MiB。STEP、3MF和图片保存文件后进入工程审核，不宣称已经解析实体或生成刀路。几何分析尚未替代真实切片、壁厚和加工公差检查。

## 多端与正式部署

- 托管版使用私人站点身份、D1 工作空间和 R2 文件；本地版使用 SQLite 和本地沙盒会话。它们的数据互不自动同步。
- 原生 App 不能直接继承网页登录 Cookie；微信身份、App 登录、文件选择、支付和通知需分别接入。
- 三星归入 Android 目标；原生鸿蒙需要独立适配，当前没有 HAP 工程或真机结果。
- SQLite 本地服务不应直接作为公开商业服务。默认只监听本机，容器示例也仅发布回环端口。
